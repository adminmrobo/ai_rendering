렌더링을 거꾸로 돌리면 — 정답표 없이 배우는 AI 렌더링

핵심 질문 · 사람이 정답을 붙여 주지 않아도, 사진만 보고 3D 장면을 배울 수 있을까?

컴퓨터는 매 순간 3D 장면을 2D 그림으로 납작하게 만든다. 이것이 렌더링이다. 이번 편은 이 화살표를 뒤집는다. 장면을 짐작해 그려 보고, 실제 사진과 비교하고, 틀린 만큼 고친다. 그러면 사진 자체가 채점표가 된다. 사다리 다섯 칸을 올라가며 래스터화에서 NeRF의 생각까지 가고, 마지막에는 우리 그래픽카드 안에서 매일 돌아가는 DLSS를 만난다.

1기초

렌더링 — 3D를 2D로 납작하게

모델: 그림 = 렌더(장면 변수)일상: 그림자놀이

일상으로 치면

손전등 앞에 손을 대면 벽에 그림자가 생긴다. 손 두 개가 겹치면 앞에 있는 손이 뒤 손을 가린다. 벽(2D)에는 손(3D)의 모양만 남고 거리는 사라진다.

모델에서는

3D 물체를 이루는 삼각형을 화면에 투영하고, 삼각형이 덮는 픽셀을 찾고(커버리지), 한 픽셀을 여럿이 덮으면 카메라에 가장 가까운 것만 남긴다(오클루전). 픽셀마다 가장 가까운 거리를 적어 두는 표가 Z-버퍼다.

초보자를 위한 풀이 — 렌더링 세 단계

  1. 투영 — 3D 점을 화면 위 점으로 옮긴다. 멀수록 작게 보이게 하면 원근 투영이다.
  2. 래스터화 — 화면 픽셀마다 "이 픽셀의 중심이 삼각형 안에 있나?"를 검사한다. 위 그림의 칠해진 칸이 커버리지다.
  3. 깊이 비교 — 여러 삼각형이 같은 픽셀을 덮으면 z가 가장 작은(가까운) 것만 남긴다. Z-버퍼를 끄면 나중에 그린 삼각형이 무조건 덮어써서, 먼 물체가 앞으로 튀어나오는 오류가 생긴다.

왜 하필 삼각형인가? 점 세 개는 늘 한 평면 위에 있고(평평함), 삼각형은 늘 볼록해서 안팎 검사가 간단하다. 작은 삼각형을 많이 쓰면 어떤 곡면도 근사할 수 있고, 꼭짓점 세 개의 값을 섞어 안쪽 어느 점의 색이든 낼 수 있다(무게중심 좌표). GPU는 이 계산에 맞춰 만들어져 있다.

이 칸의 한계 → 렌더링은 장면 → 그림 한 방향만 간다. 우리 미션은 반대다. 사진만 있고, 그 사진을 만든 장면을 모른다. 그래서 다음 칸에서 화살표를 뒤집는다.

수식으로 보기 — 투영과 무게중심 좌표

핀홀 카메라에서 점 (x, y, z)는 화면의 u = f·x / z, v = f·y / z로 간다(f는 초점 거리). z로 나누기 때문에 같은 크기도 멀면 작게 찍힌다.

화면의 점 p가 삼각형 (a, b, c) 안에 있는지는 무게중심 좌표 (α, β, γ)로 본다: p = α·a + β·b + γ·c, α + β + γ = 1. 세 값이 모두 0 이상이면 안이다. 같은 (α, β, γ)로 꼭짓점의 색·깊이를 섞으면 그 픽셀의 색과 깊이가 나온다.

2뒤집기

역렌더링 — 짐작하고, 그리고, 비교하고, 고친다

모델: 장면 = argmin ‖렌더(장면) − 사진‖²일상: 그림자만 보고 손 모양 맞히기

일상으로 치면

벽의 그림자만 보고 손 모양을 맞히는 놀이. 손을 이리저리 바꿔 보며 내 그림자가 벽의 그림자와 같아질 때까지 고친다.

모델에서는

장면 변수를 짐작해 렌더링하고, 찍힌 사진과 픽셀마다 차이를 잰다(손실). 손실이 줄어드는 쪽으로 장면 변수를 조금씩 고친다. 이것이 역렌더링이다. 공식으로 한 번에 푸는 게 아니라 찾아 나서는 일이다.

초보자를 위한 풀이 — 사람은 맞추는데 컴퓨터는 왜 못 맞추나

  1. 슬라이더로는 누구나 원을 정답에 맞출 수 있다. 눈으로 "오른쪽으로 더"를 보기 때문이다.
  2. 컴퓨터에게 "오른쪽으로 더"를 알려 주는 숫자가 기울기다. 위치를 아주 조금 옮겼을 때 손실이 얼마나 변하는지 잰다.
  3. 그런데 원의 경계가 "안이면 1, 밖이면 0"으로 딱딱하면, 아주 조금 옮겨서는 어떤 픽셀도 안팎이 바뀌지 않는다. 손실이 그대로이니 위치 기울기는 0이다.
  4. 그래서 "컴퓨터에게 맡기기"를 누르면 위치와 반지름은 꿈쩍도 안 하고, 기울기가 살아 있는 밝기만 움직인다. 원이 엉뚱한 곳에 있으니 차라리 어둡게 해서 손실을 줄이는 쪽으로 도망간다.

이 칸의 한계 → 렌더링이 계단처럼 끊기면 "어느 쪽으로 고칠지" 신호가 오지 않는다. 다음 칸에서 경계를 부드럽게 만들어 신호를 살린다.

3미분

미분 가능한 렌더링 — 경계를 살짝 번지게

모델: 덮임 = σ((r − d) / τ)일상: 붓으로 경계를 번지게 칠하기

일상으로 치면

칼로 자른 듯한 그림자 대신 경계가 살짝 번진 그림자를 쓴다. 손을 조금만 옮겨도 번진 가장자리의 밝기가 조금 변해서, 어느 쪽으로 가면 더 비슷해지는지 알 수 있다.

모델에서는

픽셀이 원에 덮인 정도를 0 또는 1이 아니라 0~1 사이의 부드러운 값(시그모이드)으로 계산한다. 그러면 렌더링 전체를 미분할 수 있고, 손실의 기울기가 위치·반지름까지 흘러간다. 이것이 미분 가능한 렌더링이다.

수식으로 보기 — 기울기가 어떻게 위치까지 가나

픽셀 i의 밝기: Iᵢ = c · σ((r − dᵢ) / τ), dᵢ = ‖pᵢ − (cx, cy)‖, σ(z) = 1 / (1 + e⁻ᶻ).

손실 L = (1/N) Σᵢ (Iᵢ − Tᵢ)². 연쇄 법칙으로 ∂L/∂cx = (2/N) Σᵢ (Iᵢ − Tᵢ) · c · σ′(·) · (1/τ) · (pᵢ,ₓ − cx) / dᵢ.

σ′는 경계 근처(|r − dᵢ| ≲ 3τ)에서만 0이 아니다. 딱딱한 경계는 τ → 0인 극한이라 σ′가 경계 바로 위에서만 무한대, 나머지는 0이 된다. 그래서 유한한 걸음으로는 기울기를 얻지 못한다. 이 페이지의 계산은 수치 미분(아주 조금 옮겨 보고 차이를 잼)과 Adam(걸음 크기를 알아서 조절하는 경사 하강)을 쓴다.

모델: L = Σ카메라 Σ픽셀 (그린 색 − 찍힌 색)²일상: 손전등 여러 개로 그림자 보기

일상으로 치면

손전등 하나로 만든 그림자는 "큰 손을 멀리"와 "작은 손을 가까이"를 구별하지 못한다. 손전등을 옆에서 하나 더 비추면 그림자가 옆으로 비켜나는 정도가 거리에 따라 달라져, 크기와 거리가 함께 정해진다.

모델에서는

카메라 위치를 아는 사진 여러 장을 모두 다시 그려 내도록 장면을 고친다. 사람이 붙인 라벨은 없다. 찍힌 사진 자체가 정답이다. 데이터 안에서 정답을 스스로 만들어 쓰는 이 방식을 자기 지도 학습이라 부른다. NeRF는 이 생각으로 3D 장면을 신경망 하나에 담는다[1].

강의 때 "이건 비지도 학습인가?"라는 질문이 나왔다. 라벨이 없다는 점은 비지도와 같지만, 분명한 채점 기준(재구성 손실)이 있으므로 자기 지도 학습이라 부르는 편이 정확하다. 레고로 치면 "색끼리 묶기"(비지도)가 아니라 "설명서 없이 완성 사진 여러 장만 보고 조립하기"다.

NeRF의 채점표. 사진의 픽셀 하나 = 카메라에서 쏜 광선 하나 r. 신경망은 광선 위 점들의 (위치 x, y, z + 보는 방향 θ, φ)를 받아 색과 밀도를 내고, 이를 광선을 따라 쌓아 픽셀 색 Ĉ(r)을 만든다. 손실은 거친 네트워크와 세밀한 네트워크의 색 오차를 더한 것이다[1]:

L = Σr [ ‖Ĉc(r) − C(r)‖² + ‖Ĉf(r) − C(r)‖² ]   ← C(r)은 찍힌 사진의 색. 사람이 만든 것이 아니다
  • 위치 인코딩 — 신경망은 부드러운 모양부터 배우려는 버릇이 있어 잔무늬를 놓친다. 좌표를 sin·cos 여러 주파수로 늘려 넣으면 고친다[1][6].
  • 계층적 샘플링 — 거친 네트워크로 물체가 있을 만한 곳을 먼저 찾고, 그곳만 세밀한 네트워크로 촘촘히 본다.
  • Neural Volumes — 여러 각도 사진을 인코더·디코더로 3D 볼륨(점마다 색과 불투명도)으로 펼치고, 광선을 쏴 다시 그린 사진과 L2 차이를 줄인다. 불투명도를 [0, ∞)로 열어 기울기가 막히지 않게 했다[2].
  • 3D 가우시안 스플래팅 — 장면을 작은 반투명 타원 수십만 개로 표현하고 흩뿌리듯 그린다. 채점 방식은 같고, 그리기가 실시간 수준으로 빠르다[3].

손실이 0이면 정답일까? 위 실험에서 카메라 1대일 때 출발점 A와 B는 둘 다 손실이 거의 0인데 서로 다른 답(크기 1.44·거리 7.19, 크기 0.49·거리 2.46)에 도착했다. 낮은 손실은 "주어진 사진들과 맞는다"는 뜻일 뿐이다. 학습에 쓰지 않은 각도에서 확인해야 한다. 그 밖에 지역 최소값, 평평한 지대, 과적합, 사람 눈과 다른 픽셀 제곱 오차도 함정이다.

이 칸의 한계 → NeRF식 학습은 장면 하나마다 수천~수만 걸음을 새로 배우고, 그림 한 장을 그릴 때도 광선마다 많은 점을 신경망에 물어야 해서 게임처럼 1초에 수십 장 그리기 어렵다. 또 정답이 "찍힌 사진"이라 사진보다 선명한 그림은 배울 수 없다. 정답을 사진 대신 더 비싸게 그린 렌더링으로 바꾸면 어떨까? 다음 칸.

생성 AI로 치면

글이나 사진 한 장으로 3D 물체를 만드는 생성 AI들도 마지막에는 이 고리를 쓴다. 3D 표현(NeRF나 가우시안)을 여러 각도에서 렌더링하고, 그 그림이 그럴듯한지 이미지 모델로 채점해 3D를 고친다. 채점표가 "찍힌 사진"에서 "이미지 모델의 판단"으로 바뀌었을 뿐 구조는 같다.

비유의 한계: 이미지 모델의 채점은 사진처럼 정확한 정답이 아니어서, 앞뒤가 다른 얼굴이 생기는 등 각도 사이의 일관성이 깨지기 쉽다.

생성 AI로 치면 — DLSS 5

DLSS 5는 해상도를 키우는 것을 넘어, 렌더링이 끝난 프레임에 AI가 빛과 재질을 덧그리는 "뉴럴 렌더링"이다[15]. 정답 렌더링을 흉내 내던 업스케일러가 이제 "더 그럴듯한 그림"을 만드는 생성 모델 쪽으로 한 걸음 옮긴 셈이다. 그래서 생성 AI와 같은 질문이 따라온다. 공개 초기에는 인물의 얼굴을 원작과 다르게 바꾸고, 게임의 미술 방향을 개발자가 의도하지 않은 쪽으로 바꾼다는 비판이 있었다[14]. 계산 부담도 커서, 켜면 프레임 속도가 약 50~60% 줄 수 있다는 NVIDIA의 수치가 소개되어 있다[14].

비유의 한계: DLSS 5는 형태를 바꾸지 않고 한 프레임을 받아 한 프레임을 내는 결정적(같은 입력 → 같은 출력) 모델이라고 NVIDIA는 설명한다[15]. 매번 다른 그림을 뽑는 이미지 생성 AI와는 다르다.

현장에 옮기면

디지털 트윈 화면, 로봇 비전 시뮬레이터, 건축 시각화에서 "적게 그리고 AI로 채우기"를 쓸 때 점검할 것: ① 엔진이 정확한 모션 벡터를 내는가(투명·파티클 레이어는 따로), ② 계기판 숫자 같은 UI는 업스케일 뒤에 얹는가, ③ 판정에 쓰는 영상(검사·측정)은 AI가 채운 픽셀이 아닌 실제 렌더 픽셀로 하는가, ④ 생성 프레임의 지연이 조작에 문제없는가, ⑤ 새 장면 종류는 출시 전 고스팅 시험을 따로 하는가.

비유의 한계: 게임과 달리 측정·검사 영상에서는 "그럴듯한 픽셀"이 오히려 위험할 수 있다. 화질 점수(PSNR)가 높아도 결함 하나를 지우면 실패다.

연속·불연속옛 네모 픽셀 게임 대 요즘의 부드러운 게임화면이 부드러워 보이는 것과 계산을 미분할 수 있는 것은 다르다. 요즘 게임도 삼각형 경계 판정은 딱딱하다
자기 지도 학습설명서 없이 완성 사진만 보고 레고 조립사람은 몇 번이면 감을 잡지만, NeRF는 장면 하나에 수만 번 고친다
DLSS스케치 여러 장 겹치기스케치를 겹치는 몫 말고도, 정보가 없는 곳을 그럴듯하게 채우는 신경망의 몫이 있다

코드 1 · 사진 한 장으로 장면 되찾기 — 부드러운 경계 대 딱딱한 경계
# 코드 1 · 사진 한 장만 보고 장면을 되찾기 — 미분 가능한 렌더링(역렌더링)
import numpy as np
np.random.seed(0)
N = 32
ys, xs = np.mgrid[0:N, 0:N] / (N - 1)          # 화면 픽셀 좌표 0~1

def render(p, soft=True, tau=0.03):
    """장면 변수 p = [cx, cy, r, 밝기] → 32x32 이미지"""
    cx, cy, r, c = p
    d = np.sqrt((xs - cx)**2 + (ys - cy)**2)
    if soft:   # 경계를 부드럽게: 연속 함수 → 미분 가능
        cover = 1 / (1 + np.exp(-np.clip((r - d) / tau, -50, 50)))
    else:      # 안이면 1, 밖이면 0: 불연속 함수 → 미분 0
        cover = (d < r).astype(float)
    return c * cover

def loss(p, target, soft):
    return np.mean((render(p, soft) - target) ** 2)

def grad(p, target, soft, h=1e-4):          # 수치 미분
    g = np.zeros(4)
    for i in range(4):
        e = np.zeros(4); e[i] = h
        g[i] = (loss(p + e, target, soft) - loss(p - e, target, soft)) / (2 * h)
    return g

true_p  = np.array([0.62, 0.40, 0.22, 0.90])   # 정답 장면 (모델은 모른다)
target  = render(true_p, soft=True)             # 우리가 가진 것은 이 사진 한 장뿐
start_p = np.array([0.35, 0.60, 0.12, 0.40])   # 아무렇게나 시작

for soft in (True, False):
    p = start_p.copy(); lr = 0.02; m = np.zeros(4); v = np.zeros(4)
    print(f"\n[{'부드러운 경계(연속)' if soft else '딱딱한 경계(불연속)'}]")
    for step in range(301):
        if step in (0, 10, 50, 100, 300):
            print(f"걸음 {step:3d} | 손실 {loss(p, target, soft):.5f} | "
                  f"cx {p[0]:.3f} cy {p[1]:.3f} r {p[2]:.3f} 밝기 {p[3]:.3f}")
        g = grad(p, target, soft)            # Adam: 걸음 크기를 알아서 조절
        m = 0.9*m + 0.1*g; v = 0.999*v + 0.001*g*g
        p -= lr * (m/(1-0.9**(step+1))) / (np.sqrt(v/(1-0.999**(step+1))) + 1e-8)
print("\n정답       | cx 0.620 cy 0.400 r 0.220 밝기 0.900")

코드 2 · 작은 DLSS 흉내 — 렌더링이 만든 정답으로 배우는 업스케일러와 모션 벡터
# 코드 2 · 작은 DLSS 흉내 — 정답 이름표 없이 "고해상도 렌더링 자신"을 정답으로 배운다
import numpy as np
np.seterr(divide="ignore")
rng = np.random.default_rng(0)
H = 64                                            # 고해상도 64x64, 저해상도 32x32

def scene(k=6):
    """무작위 원과 줄무늬가 섞인 장면을 고해상도로 '렌더링'한다"""
    ys, xs = np.mgrid[0:H, 0:H] / H
    img = np.zeros((H, H))
    for _ in range(k):
        cx, cy, r = rng.random(), rng.random(), 0.05 + 0.2 * rng.random()
        img += rng.random() / (1 + np.exp(-(r - np.hypot(xs - cx, ys - cy)) / 0.01))
    img += 0.3 * np.sin(2 * np.pi * (rng.integers(3, 9)) * (xs * rng.random() + ys))
    return (img - img.min()) / (np.ptp(img) + 1e-9)

def low(img, dx=0, dy=0):                         # 픽셀 4개 중 하나만 찍기(지터 dx,dy)
    return img[dy::2, dx::2]

def psnr(a, b):
    return 10 * np.log10(1 / np.mean((a - b) ** 2))

def patches(lo):                                  # 저해상도 픽셀마다 주변 3x3 조각
    p = np.pad(lo, 1, mode="edge")
    return np.stack([p[i:i+lo.shape[0], j:j+lo.shape[1]].ravel()
                     for i in range(3) for j in range(3)], 1)

def blocks(hi):                                   # 고해상도 2x2 블록 = 맞혀야 할 정답
    return np.stack([hi[i::2, j::2].ravel() for i in range(2) for j in range(2)], 1)

def assemble(b):
    out = np.zeros((H, H)); n = H // 2
    for k, (i, j) in enumerate([(0,0),(0,1),(1,0),(1,1)]):
        out[i::2, j::2] = b[:, k].reshape(n, n)
    return out

# ① 학습: 고해상도 렌더링 200장을 스스로 줄이고, 다시 키우는 법을 배운다 (사람 라벨 0개)
train = [scene() for _ in range(200)]
X = np.vstack([np.c_[patches(low(s)), np.ones(32*32)] for s in train])
Y = np.vstack([blocks(s) for s in train])
W = np.linalg.lstsq(X, Y, rcond=None)[0]          # 9칸+1 → 4칸 '업스케일 필터'

# ② 시험: 처음 보는 장면 50장
test = [scene() for _ in range(50)]
res = {"가장 가까운 픽셀 복사": [], "배운 업스케일러(1장)": [],
       "지터 4장 합치기 · 멈춘 화면": [], "지터 4장 · 움직임, 모션 벡터 없음": [],
       "지터 4장 · 움직임, 모션 벡터 사용": []}
for s in test:
    lo = low(s)
    res["가장 가까운 픽셀 복사"].append(psnr(np.kron(lo, np.ones((2, 2))), s))
    res["배운 업스케일러(1장)"].append(psnr(assemble(np.c_[patches(lo), np.ones(32*32)] @ W), s))
    acc = np.zeros((H, H))                        # 프레임마다 카메라를 반 픽셀씩 흔든다
    for dy in (0, 1):
        for dx in (0, 1):
            acc[dy::2, dx::2] = low(s, dx, dy)
    res["지터 4장 합치기 · 멈춘 화면"].append(min(psnr(acc, s), 60.0))
    # 화면이 프레임마다 오른쪽으로 2픽셀씩 움직이면? (마지막 프레임 t=3이 '지금')
    now = np.roll(s, 6, axis=1)
    bad = np.zeros((H, H)); good = np.zeros((H, H))
    for t, (dy, dx) in enumerate([(0,0),(0,1),(1,0),(1,1)]):
        frame = np.roll(s, 2 * t, axis=1)          # t번째 프레임의 고해상도 장면
        bad[dy::2, dx::2] = low(frame, dx, dy)      # 그냥 겹치면 잔상(고스팅)
        moved = np.zeros((H, H)); moved[dy::2, dx::2] = 1
        tmp = np.zeros((H, H)); tmp[dy::2, dx::2] = low(frame, dx, dy)
        sh = 2 * (3 - t)                            # 모션 벡터: '지금'까지 더 갈 거리
        good = np.where(np.roll(moved, sh, axis=1) > 0, np.roll(tmp, sh, axis=1), good)
    res["지터 4장 · 움직임, 모션 벡터 없음"].append(psnr(bad, now))
    res["지터 4장 · 움직임, 모션 벡터 사용"].append(min(psnr(good, now), 60.0))

print("시험 장면 50장 평균 PSNR (높을수록 원본과 같음, dB)")
for k, v in res.items():
    print(f"  {k:26s} {np.mean(v):6.2f}")
