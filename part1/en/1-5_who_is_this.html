Who Is This Face? Why front views match and side views fail

Key question · With just four labeled photos (one front view per character), can we recognize the rest? Why do side and back views break it?

In Part 1 you grouped without labels (1-2), folded (1-3), and filled in masked parts (1-4). The final mission is to recognize people. With front-facing photos, Part 1’s tools alone work well. But when photos with turned heads are mixed in, performance collapses. We find the numbers behind this failure and fix it with Part 1’s tools. This failure is the starting point for Part 2 (3D from photos) and Part 3 (from any angle).

Why this topic

1Recognition is a problem of “closeness”

Face recognition began with finding the known photo closest to a new one. The 1991 study that measured distance with eigenfaces is the classic example.[1]

2It breaks when the head turns

A different person at the same angle can look more similar than the same person at a different angle. This is a long-standing problem in face recognition. Eigenface research also showed its limit against changes in angle.[1][2]

3What to measure with

Features that drop position, such as color ratios (color histograms), change less when the object turns. In 1991, Swain and Ballard showed that objects can be recognized from color ratios alone.[3]

The math — giving a name

Known photos (x_j, y_j), j = 1…4. Name of an unknown photo x: ŷ = y_{j*}, j* = argmin_j ‖φ(x) − φ(x_j)‖². φ is the feature: pixels are the 768 values from the square around the person, resampled to 16×16; color ratio is 8 numbers, the share of each of 8 color groups. The math — angle changes the distance

Photo x (person p, angle θ). The pixel distance ‖x(p, θ) − x(q, 0)‖² grows with θ even for the same person (p = q). Conversely, different people (p ≠ q) with similar θ can have a small distance. For recognition to work, the distance for “same person, different angle” must always be smaller than for “different person.” Pixel distance breaks this on side views. Adding labels only at the front fills in just the region near θ = 0.

3Features

Features that wobble less — measuring by color ratio

Model: feature = the ratio of each of 8 color groups (k-means from 1-2) · position is discardedEveryday: even from the back, “pink hair, two topknots” means the assistant

In everyday terms

To recognize a friend from the back, we look at things like hair color or bag color instead of the face. Wherever they stand and whichever way they face, the color stays the same. But two people carrying bags of the same color can be confused.

In the model

The pixel colors of the 240 unknown photos are grouped into 8 clusters with the k-means method from 1-2 (no names used). Counting “what percent is this color” in each photo gives a feature of 8 numbers, the color ratio. Because pixel positions are discarded, it wobbles less when the head turns (invariance)[3]. The known photos are still one front photo each.

The math — color ratio (color histogram)

Color cluster centers c₁…c₈ (k-means). Feature of photo x: h_k = (1/n) Σ_{non-background pixel i} 1[nearest center(xᵢ) = c_k]. Even if pixel positions are shuffled, h stays the same, so when the object turns or moves, only the share of visible colors changes. Swain and Ballard recognized objects by the overlap of two histograms.[3] Here we used the distance ‖h − h′‖².

Code 1 · Who is this face? — bust photo, four labels, pixels vs. color ratio, accuracy by front, side, and back
# 코드 1 · 이 얼굴은 누구? — 네 캐릭터 3D 흉상을 아무 각도에서 찍고, 이름표 4장(정면)으로 알아보기
import numpy as np, time
RES, HALF, CY, BG = 40, 1.95, -.35, np.array([.10, .10, .16])
C = dict(skin=(.98,.80,.68), black=(.13,.13,.16), white=(.93,.94,.97), gray=(.78,.78,.82), pink=(.96,.55,.70), navy=(.16,.20,.45), lav=(.74,.66,.92), blue=(.30,.55,.95),
         helm=(.20,.30,.62), flyb=(.16,.15,.20), red=(.92,.22,.22), yellow=(.98,.85,.25), screen=(.06,.06,.09), cyan=(.35,.80,.98), vest=(.18,.18,.22),
         beige=(.92,.88,.78), green=(.06,.10,.08), mint=(.70,.95,.70), bead=(.62,.26,.18))
NAME = ["박사", "조수", "초파리", "주판봇"]
def model(k):
    S = [((0, -1.95, 0), 1.15, "body")]
    if k == 0: S += [((0, 0, 0), 1, "head")]
    if k == 1: S += [((0, 0, 0), 1, "head"), ((-.78, .72, -.12), .42, "bun"), ((.78, .72, -.12), .42, "bun")]
    if k == 2: S += [((0, 0, 0), .95, "head"), ((-.42, .05, .72), .36, "eye"), ((.42, .05, .72), .36, "eye"), ((-1.15, -1.4, -.4), .55, "wing"), ((1.15, -1.4, -.4), .55, "wing")]
    if k == 3: S += [((0, .05, 0), 1.05, "head"), ((0, 1.3, 0), .16, "ant")]
    return S
def color(k, part, n):
    x, y, z = n
    if part == "body":
        if k == 3: return C["beige"]
        if k == 2: return C["flyb"] if (z > .3 and abs(x) < .35) else C["white"]
        if k == 0: return C["vest"] if (z > .4 and abs(x) < .3) else C["white"]
        return C["lav"] if y > .72 else C["white"]
    if part in ("bun",): return C["pink"]
    if part == "eye": return C["red"]
    if part == "wing": return C["gray"]
    if part == "ant": return C["bead"]
    if k == 0:
        if z > .2 and y < .45: return C["black"] if (abs(y - .05) < .07 and abs(x) < .62) else C["skin"]
        return C["white"] if (abs(x + .15) < .12 and y > .3) else C["black"]
    if k == 1:
        if z > .25 and y < .42: return C["blue"] if ((abs(x) - .36)**2 + (y - .02)**2 < .013) else C["skin"]
        return C["navy"] if (abs(x - .22) < .09 and y > -.1) else C["pink"]
    if k == 2: return C["helm"] if y > .1 else C["flyb"]
    if z > .45 and abs(y) < .42 and abs(x) < .62: return C["mint"] if min((x - .25)**2, (x + .25)**2) + (y - .05)**2 < .014 else C["green"]
    return C["beige"]

def photo(k, deg, seed):
    """각도 deg에서 찍은 40×40 사진. 자리(±0.15)·크기(0.9~1.1배)는 사진마다 다르다"""
    r = np.random.default_rng(seed); ox, oy = (r.random() - .5)*.3, (r.random() - .5)*.3; sc = .9 + .2*r.random(); th = np.radians(deg); c, s = np.cos(th), np.sin(th)
    img = np.tile(BG, (RES, RES, 1)); S = model(k); L = np.array([.3, .6, .74])
    for py in range(RES):
        for px in range(RES):
            X = ((px + .5)/RES*2 - 1)*sc + ox; Y = (1 - (py + .5)/RES*2)*sc + oy
            o = np.array([c*X*HALF - s*10, Y*HALF + CY, s*X*HALF + c*10]); d = np.array([s, 0, -c])        # 카메라를 -th만큼 돌린 광선
            best = None
            for cen, rad, part in S:
                oc = o - cen; b = oc @ d; h = b*b - oc @ oc + rad*rad
                if h >= 0:
                    t = -b - np.sqrt(h)
                    if t > 1e-4 and (best is None or t < best[0]): best = (t, cen, rad, part)
            if best:
                t, cen, rad, part = best; n = (o + d*t - cen)/rad; nw = np.array([c*n[0] + s*n[2], n[1], -s*n[0] + c*n[2]])
                img[py, px] = np.minimum(1, np.array(color(k, part, n))*(.35 + .75*max(0, nw @ L)))
    return img

def crop(img, to=16):                                            # 자리·크기 맞추기
    fg = np.abs(img - BG).sum(-1) > .05; ys, xs = np.nonzero(fg); cx, cy = (xs.min() + xs.max() + 1)/2, (ys.min() + ys.max() + 1)/2
    s = max(xs.max() - xs.min(), ys.max() - ys.min()) + 1; g = (np.arange(to) + .5)/to*s - s/2 - .5
    fx, fy = np.meshgrid(np.round(cx + g).astype(int), np.round(cy + g).astype(int)); ok = (fx >= 0) & (fy >= 0) & (fx < RES) & (fy < RES)
    out = np.tile(BG, (to, to, 1)); out[ok] = img[fy[ok], fx[ok]]; return out.ravel()

t0 = time.time(); rng = np.random.default_rng(31)
known = [(k, photo(k, 0, 9 + k)) for k in range(4)]                                   # 이름표 4장: 정면 한 장씩
front = [(k, a, photo(k, a, 500 + k*1000 + i)) for k in range(4) for i, a in enumerate(rng.uniform(-30, 30, 30))]
anyang = [(k, a, photo(k, a, 100 + k*1000 + i)) for k in range(4) for i, a in enumerate(rng.uniform(0, 360, 30))]
P = np.array([p.reshape(-1, 3)[np.abs(p.reshape(-1, 3) - BG).sum(1) > .05] for _, _, p in front + anyang], dtype=object)
pix = np.vstack(list(P)); cent = pix[rng.choice(len(pix), 8, replace=False)]
for _ in range(12):                                              # 색 8묶음 (1-2의 k-평균, 이름 안 씀)
    lab = ((pix[:, None] - cent[None])**2).sum(-1).argmin(1); cent = np.array([pix[lab == j].mean(0) if (lab == j).any() else cent[j] for j in range(8)])
def colfeat(img):
    q = img.reshape(-1, 3); q = q[np.abs(q - BG).sum(1) > .05]; return np.bincount(((q[:, None] - cent[None])**2).sum(-1).argmin(1), minlength=8)/len(q)
def judge(test, feat):
    K = np.array([feat(p) for _, p in known]); out = {"앞": [], "옆": [], "뒤": []}
    for k, a, p in test:
        guess = ((K - feat(p))**2).sum(1).argmin(); a = a % 360; part = "앞" if (a <= 45 or a >= 315) else ("뒤" if 135 <= a <= 225 else "옆"); out[part].append(guess == k)
    allv = sum(out.values(), []); return 100*np.mean(allv), {k: (f"{100*np.mean(v):.0f}%" if v else "-") for k, v in out.items()}
for name, test in [("정면 사진 120장 (−30°~30°)", front), ("아무 각도 사진 120장", anyang)]:
    print(name)
    for fn, f in [("픽셀 그대로 (자리·크기 맞춤)", crop), ("색 비율 (색 8묶음)", colfeat)]:
        acc, parts = judge(test, f); print(f"  {fn:<22} {acc:5.1f}%  앞·옆·뒤: {parts}")
print(f"이름표 4장 · 계산 {time.time() - t0:.0f}초")

Code 2 · What happens when you rotate handwritten digits — labels from upright digits, tests on rotated digits (scikit-learn)
# 코드 2 · 손글씨 숫자를 돌리면 — 똑바른 숫자로만 이름표를 주고, 돌린 숫자로 시험 (scikit-learn)
import numpy as np, time
from sklearn.datasets import load_digits
from scipy.ndimage import rotate
t0 = time.time()
X, y = load_digits(return_X_y=True); X = X.reshape(-1, 8, 8) / 16
r = np.random.default_rng(0); idx = r.permutation(len(X)); known, test = idx[:10*5], idx[300:700]   # 이름표 50장(숫자마다 약 5장, 똑바름)
def turn(a, deg): return np.clip(rotate(a, deg, reshape=False, order=1), 0, 1)
yy, xx = np.mgrid[0:8, 0:8]; ring = np.minimum((np.hypot(yy - 3.5, xx - 3.5)).astype(int), 4)
def rings(a): return np.array([a[ring == k].mean() for k in range(5)] + [a.mean(), (a > .5).mean()])   # 가운데서 거리별 잉크 양: 돌려도 거의 같다
def nn(F_known, F_test): return y[known][((F_test[:, None] - F_known[None])**2).sum(-1).argmin(1)]
print("이름표: 똑바른 숫자 50장 · 시험: 400장을 각도만큼 돌림 · 운으로 맞히면 10%")
print("  각도 | 픽셀 그대로 | 고리별 잉크 양 (자리 버림)")
for deg in [0, 30, 60, 90, 180]:
    T = np.array([turn(X[i], deg) for i in test])
    p1 = nn(X[known].reshape(len(known), -1), T.reshape(len(T), -1)); p2 = nn(np.array([rings(X[i]) for i in known]), np.array([rings(t) for t in T]))
    print(f"  {deg:4d}° |   {100*(p1 == y[test]).mean():5.1f}%    |   {100*(p2 == y[test]).mean():5.1f}%")
print(f"계산 {time.time() - t0:.1f}초")

        Example values and illustrative models

        • The photos in panels ①②③ and in the duel: the four characters' 3D busts, hand-built from spheres (head, bun, big eyes, wings, antenna, body), rendered by this page as 40×40 photos with ray tracing. Position (±0.15) and size (0.9–1.1×) are random for each photo. These are not the character pack's artwork.
        • Known-name photos: one frontal (0°) photo per character. AbaBot's picks: 10 frontal (−30° to 30°) photos each. Unknown-name photos: 120 frontal photos (−30° to 30°) and 120 any-angle photos (fixed seed). "Front" is 0±45°, "back" is 180±45°, and everything else is "side."
        • The 8 color groups are the pixel colors of 240 unknown-name photos, grouped with k-means (12 iterations, seed 3). No names were used.
