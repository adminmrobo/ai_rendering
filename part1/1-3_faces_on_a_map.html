왜 이 주제인가

1숫자가 너무 많다

그림, 소리, 문장, 고객 기록. 자료 하나가 숫자 수천 개다. 사람이 보려면, 그리고 계산을 줄이려면 숫자 몇 개로 접어야 한다.

2가장 오래된 접는 법

주성분 분석은 자료가 가장 크게 퍼진 방향을 찾는 방법으로 1901년 피어슨이 처음 제안했다[1]. 지금도 자료를 처음 볼 때 가장 먼저 쓰는 도구다[3].

3얼굴의 "고유 얼굴"

1991년 턱과 펜틀런드는 얼굴 사진의 주성분을 "고유 얼굴(eigenface)"이라 부르고, 얼굴을 몇 개의 숫자로 접어 알아보는 데 썼다[2]. 1-5에서 이 생각을 다시 만난다.

모델에서는

주성분 분석은 240장이 가장 크게 다른(출렁이는) 방향을 찾는다. 그 방향이 주성분이고, 그림으로 보이면 고유 얼굴이다. 얼굴에서 평균 얼굴을 빼고 고유 얼굴과 픽셀마다 곱해 더하면 숫자 하나가 나온다. 1번, 2번 고유 얼굴로 두 숫자를 만들면 지도 위 점(잠재 공간)이 된다. 모든 픽셀이 조금씩 섞이므로, 그림이 조금 옮겨져도 점은 크게 흔들리지 않는다. 지도의 쓸모는 이웃 맞히기로 잰다.

수식으로 보기 — 주성분 분석

그림 n장 xᵢ ∈ ℝ³⁰⁷², 평균 μ. 가운데로 옮긴 행렬 X̃ = [x₁ − μ, …, xₙ − μ]. 공분산 Σ = (1/n) X̃ᵀX̃의 고유벡터 p₁, p₂, …(고윳값 λ₁ ≥ λ₂ ≥ …)가 주성분이다. 점 zᵢₖ = (xᵢ − μ) · pₖ. 3,072×3,072 행렬 대신 n×n 행렬 X̃X̃ᵀ의 고유벡터 v를 거듭제곱법으로 구하고 p = X̃ᵀv / √λ로 바꾼다. 고유 얼굴을 계산할 때 쓰는 고전적인 지름길이다[2].

그림자 놀이에서 손 모양 몇 가지를 조금씩 바꿔 겹치면 개, 새, 토끼가 된다. 기본 모양 몇 개와 "얼마나"만 알면 여러 그림을 다시 만들 수 있다. 기본 모양이 적으면 대충, 많으면 자세히.

모델에서는

고유 얼굴은 240장이 가장 크게 다른 방향부터 차례로 뽑은 기본 모양이다. 지도 위 숫자 z는 "그 기본 모양을 얼마나"다. 평균 얼굴에 z × 고유 얼굴을 더하면 얼굴이 돌아온다(복원). 고유 얼굴이 담은 출렁임(분산)의 몫이 클수록 적은 숫자로 많이 돌아온다.

수식으로 보기 — 복원과 분산의 몫

복원 x̂ = μ + Σₖ₌₁ᴷ zₖ pₖ, 오차 ‖x − x̂‖²의 평균은 버린 고윳값의 합 Σₖ₌ᴷ₊₁ λₖ(÷ 픽셀 수)과 같다. 그래서 K개가 담은 분산의 몫 Σₖ₌₁ᴷ λₖ / Σ λ이 클수록 오차가 작다. 주성분은 같은 개수의 직선 방향 중 이 오차를 가장 작게 만드는 방향이다[1][3]. 이 페이지의 오차는 픽셀값(0~1)의 제곱 평균이고, 0~1 밖으로 나간 값은 잘라 냈다.

3산책

지도 위 산책 — 직선 지도의 한계

모델: z(t) = (1 − t)·zA + t·zB → 펴기 = (1 − t)·얼굴A + t·얼굴B일상: 사진 두 장을 겹쳐 인화하면 유령 같은 얼굴

일상으로 치면

필름 두 장을 겹쳐 인화하면 두 사람이 반투명하게 겹친 유령 사진이 나온다. "두 사람의 중간쯤 되는 새 얼굴"이 나오지는 않는다. 중간 얼굴을 그리려면 눈은 눈끼리, 머리는 머리끼리 맞춰 옮겨야 한다.

모델에서는

주성분 지도의 펴기는 덧셈과 곱셈뿐이다(선형). 그래서 지도 위 두 점 사이를 직선으로 걸으며 펴면, 두 얼굴을 반투명하게 겹친 것과 똑같다. 지도 한가운데(아무 얼굴도 없는 빈 곳)에서 펴면 평균 얼굴, 모든 캐릭터가 겹친 유령이 나온다. 휘어진 지도, 빈 곳을 그럴듯하게 채우는 지도는 비선형 방법이 필요하다[4].

행동으로 보기 — 지도 위의 길과 빈 곳

초보자를 위한 풀이 — 지도가 곧은 것의 장점과 한계

  1. 걷기 = 겹치기. 두 줄의 차이는 컴퓨터 계산 오차 수준이다. 가운데에서는 두 캐릭터가 반씩 겹친 유령이 된다.
  2. 빈 곳은 유령. 지도 한가운데는 평균 얼굴이다. 누구의 얼굴도 아니다.
  3. 곧은 지도의 장점. 계산이 빠르고(고윳값 문제 하나), 같은 자료면 언제나 같은 답이 나오고, 축(고유 얼굴)을 그림으로 보며 설명할 수 있다. 그래서 지금도 자료를 처음 볼 때 먼저 쓴다.

이 칸의 한계 → 휘어진 지도를 배우려면, 접는 쪽과 펴는 쪽을 신경망으로 바꾸고 "다시 그리기"를 맞히도록 학습시킨다. 얼굴 일부를 가리고 채우게 하면 더 단단해진다. 다음 편 1-4 「가리고 맞히기」.

수식으로 보기 — 왜 걷기 = 겹치기인가

펴기 f(z) = μ + Pz는 z에 대해 일차식이다. 그래서 f((1 − t)z_A + t z_B) = (1 − t) f(z_A) + t f(z_B). 지도 위 직선은 그림 공간의 직선(겹치기)으로 간다. 비선형 지도(t-SNE[4], 오토인코더)는 이 성질이 없어서 휘어진 길을 따라갈 수 있다. 대신 축을 그림 한 장으로 설명하기 어렵고, 같은 자료에서도 실행마다 지도가 달라질 수 있다.

주판봇

박사와 조수의 중간 얼굴을 팔려고 했는데 유령이 나오네. 이건 안 팔린다.

대결 — 숫자 두 개로 만든 지도, 누구 것이 쓸모 있나

얼굴 240장을 숫자 두 개로 찍은 지도를 만든다. 지도 위에서 그림마다 가장 가까운 점(같은 원본에서 늘린 그림은 뺌)이 같은 캐릭터인 비율로 잰다. 둘 다 이름표는 쓰지 않는다.

선택: 가장 많이 변하는 픽셀 2개
먼저 맞혀 보기:
조수

박사

주판봇의 픽셀 두 개는 출렁임은 컸지만, 그 출렁임의 많은 부분이 그림을 옮기고 뒤집은 데서 왔다. 주성분은 모든 픽셀을 섞어, 많은 픽셀이 함께 움직이는 큰 차이(분홍·흰 덩어리, 어두운 몸)를 잡는다. 숫자 수가 같아도 만드는 법이 결과를 약 45%포인트 가른다.

정리 — 접고, 펴고, 걷기

칸무엇을 했나이 편의 숫자한계 (다음을 부른 이유)
① 지도 접기주성분 2개 vs 픽셀 2개이웃 맞히기 97.9% vs 52.5% (아무 픽셀 46.3%, 전체 98.8%)두 숫자가 무엇을 담았나
② 고유 얼굴고유 얼굴과 복원1번 22.8%, 2번 8.0% · 복원 오차 2개 0.0310 → 20개 0.0153지도 위를 걸으면?
③ 지도 위 산책직선 산책, 빈 곳걷기 = 겹치기 (차이 ≈ 0) · 빈 곳 = 평균 얼굴휘어진 지도 → 1-4

비유와 그 한계

개념일상 비유비유가 틀리는 지점
지도 접기키·몸무게 두 숫자로 친구 찍기키·몸무게는 사람이 고른 숫자지만, 주성분은 자료가 스스로 정한다. 그리고 픽셀 전부를 섞은 숫자라 이름이 없다
고유 얼굴그림자 놀이의 기본 손 모양손 모양은 사람이 알아보는 모양이지만, 고유 얼굴은 밝고 어두운 얼룩이라 한눈에 뜻이 보이지 않을 때가 많다
직선 산책필름 두 장 겹쳐 인화겹친 사진은 실수지만, 주성분 지도에서는 수학적으로 꼭 그렇게 된다. 비선형 지도에서는 달라진다

코드 1은 numpy만으로 주성분 분석을 직접 짠다. 코드 2는 scikit-learn의 손글씨 숫자(8×8, 1,797장)에 같은 방법을 써서 결과가 얼굴에만 해당하는 것이 아님을 확인한다.

코드 1 · 지도 접기와 고유 얼굴 — 주성분 2개 vs 픽셀 2개, 숫자 수별 복원 오차, 직선 산책
# 코드 1 · 얼굴을 지도 위 점으로 — 주성분 분석(PCA)을 numpy로 직접: 주성분 2개 vs 픽셀 2개, 복원, 직선 산책
# 캐릭터 팩 그림 대신, 네 캐릭터를 닮은 32×32 그림을 동그라미·네모로 직접 그린다 (표정 6가지 × 늘리기 10장)
import numpy as np, time
W = 32; rng = np.random.default_rng(11)
yy, xx = np.mgrid[0:W, 0:W]
def disc(img, cx, cy, r, col): img[(xx - cx)**2 + (yy - cy)**2 <= r*r] = col
def box(img, x0, y0, x1, y1, col): img[y0:y1, x0:x1] = col

def face(who, expr):
    """who: 0 박사, 1 조수, 2 초파리, 3 주판봇 · expr: 표정 0~5 (눈·입이 조금씩 다름)"""
    img = np.zeros((W, W, 3)); img[:] = (.11, .11, .17)
    if who == 0:   box(img, 8, 20, 24, 32, (.92, .92, .95)); disc(img, 16, 13, 7, (.98, .82, .70)); box(img, 9, 4, 23, 9, (.15, .15, .18)); box(img, 15, 4, 18, 8, (.9, .9, .9))
    if who == 1:   box(img, 7, 20, 25, 32, (.80, .74, .92)); disc(img, 16, 14, 8, (.93, .55, .68)); disc(img, 8, 6, 4, (.93, .55, .68)); disc(img, 24, 6, 4, (.93, .55, .68)); disc(img, 16, 16, 5, (.99, .85, .76)); box(img, 18, 7, 20, 13, (.2, .25, .5))
    if who == 2:   disc(img, 16, 18, 9, (.18, .18, .22)); disc(img, 16, 10, 7, (.25, .35, .6)); disc(img, 6, 20, 5, (.55, .55, .65))
    if who == 3:   box(img, 7, 7, 25, 28, (.92, .87, .76)); box(img, 10, 10, 22, 19, (.09, .21, .15)); box(img, 15, 3, 17, 7, (.4, .4, .42)); disc(img, 16, 3, 2, (.62, .26, .18))   # 주판봇: 베이지 상자 몸, 짙은 초록 화면, 주판알 안테나
    ey = 13 + (expr % 3) - 1; eye = [(.3, .5, .9), (.3, .5, .9), (.95, .2, .2), (.45, .95, .65)][who]; r = 1 + (expr // 3)
    disc(img, 13, ey, r, eye); disc(img, 19, ey, r, eye)
    if who < 2: box(img, 14, 18 + expr % 2, 18 + expr % 3, 19 + expr % 2, (.6, .25, .3))
    return img

def augment(img):
    dx, dy = rng.integers(-2, 3, 2); out = np.roll(img, (dy, dx), (0, 1))
    if rng.random() < .5: out = out[:, ::-1]
    return np.clip(out * rng.uniform(.88, 1.12), 0, 1)

X, L, SRC = [], [], []
for who in range(4):
    for e in range(6):
        base = face(who, e)
        for k in range(10): X.append((base if k == 0 else augment(base)).ravel()); L.append(who); SRC.append(who*6 + e)
X, L, SRC = np.array(X), np.array(L), np.array(SRC)               # 240장 × 3,072개 숫자

t0 = time.time()
mu = X.mean(0); Xc = X - mu
U, s, Vt = np.linalg.svd(Xc, full_matrices=False)                # 주성분 = Vt의 줄들 (고유 얼굴)
lam = s**2; share = lam / lam.sum(); Z = Xc @ Vt[:20].T          # 지도 위 점 (숫자 20개까지)

def nn_acc(F):
    """지도 위 가장 가까운 점이 같은 캐릭터인 비율 (같은 원본에서 늘린 그림은 뺀다). 이름표는 채점에만"""
    D = ((F[:, None, :] - F[None, :, :])**2).sum(-1); D[SRC[:, None] == SRC[None, :]] = np.inf
    return 100 * (L[D.argmin(1)] == L).mean()

var_px = Xc.var(0); top2 = np.argsort(var_px)[-2:]; rand2 = np.random.default_rng(4).integers(0, 3072, 2)
print("① 숫자 2개로 만든 지도 — 이웃 맞히기")
print(f"  주성분 2개           {nn_acc(Z[:, :2]):5.1f}%")
print(f"  가장 많이 변하는 픽셀 2개 {nn_acc(X[:, top2]):5.1f}%")
print(f"  아무 픽셀 2개          {nn_acc(X[:, rand2]):5.1f}%")
print(f"  (참고) 숫자 3,072개 그대로 {nn_acc(X):5.1f}%")
print("② 고유 얼굴이 담은 출렁임의 몫:", " ".join(f"{100*v:.1f}%" for v in share[:6]))
print("   숫자 수 | 이웃 맞히기 | 복원 오차")
for k in [1, 2, 5, 10, 20]:
    R = np.clip(mu + Z[:, :k] @ Vt[:k], 0, 1)
    print(f"   {k:5d}   |   {nn_acc(Z[:, :k]):5.1f}%   | {((R - X)**2).mean():.4f}")
a, b = 6*10, 0                                                   # 조수 표정 0 → 박사 표정 0
walk = [np.clip(mu + ((1-t)*Z[a] + t*Z[b]) @ Vt[:20], 0, 1) for t in np.linspace(0, 1, 6)]
blend = [np.clip((1-t)*(mu + Z[a] @ Vt[:20]) + t*(mu + Z[b] @ Vt[:20]), 0, 1) for t in np.linspace(0, 1, 6)]
print(f"③ 지도 위 직선 산책 vs 두 얼굴 겹치기, 가장 큰 차이: {max(np.abs(w - c).max() for w, c in zip(walk, blend)):.1e}  (주성분은 선형이라 같다)")
print(f"계산 {time.time() - t0:.2f}초")

코드 2 · 손글씨 숫자로 확인 — 주성분, 많이 변하는 픽셀, 아무 픽셀 (scikit-learn)
# 코드 2 · 손글씨 숫자로 확인 — 같은 비교를 scikit-learn의 손글씨 숫자(8×8, 1,797장)로
import numpy as np, time
from sklearn.datasets import load_digits
from sklearn.decomposition import PCA
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import cross_val_score

t0 = time.time()
X, y = load_digits(return_X_y=True)                              # 숫자 64개짜리 그림, 이름표(0~9)는 채점에만
def nn_score(F):                                                 # 지도 위 가장 가까운 이웃으로 숫자 맞히기 (5겹 교차 검증)
    return 100 * cross_val_score(KNeighborsClassifier(1), F, y, cv=5).mean()
pca = PCA(n_components=20).fit(X); Z = pca.transform(X)
top2 = np.argsort(X.var(0))[-2:]; rand2 = np.random.default_rng(4).choice(np.where(X.var(0) > 0)[0], 2, replace=False)
print("숫자 2개로 만든 지도 — 이웃 맞히기 (10종류, 운으로 맞히면 10%)")
print(f"  주성분 2개                {nn_score(Z[:, :2]):5.1f}%")
print(f"  가장 많이 변하는 픽셀 2개 {nn_score(X[:, top2]):5.1f}%")
print(f"  아무 픽셀 2개 (빈칸 제외)  {nn_score(X[:, rand2]):5.1f}%")
print(f"  (참고) 숫자 64개 그대로    {nn_score(X):5.1f}%")
print("주성분이 담은 출렁임의 몫:", " ".join(f"{100*v:.1f}%" for v in pca.explained_variance_ratio_[:5]))
for k in [2, 5, 10, 20]:
    R = Z[:, :k] @ pca.components_[:k] + pca.mean_
    print(f"  숫자 {k:2d}개: 이웃 맞히기 {nn_score(Z[:, :k]):5.1f}% · 복원 오차 {((R - X)**2).mean():6.2f} (픽셀값 0~16)")
print(f"계산 {time.time() - t0:.1f}초")
