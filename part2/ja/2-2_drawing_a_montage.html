モンタージュを描く — 当て推量し、描き、比べ、直す

中心の問い · 写真を逆に解けないなら、3Dを当て推量で描き、写真と合わせて直すことで取り戻せるだろうか？ 何回描く必要があるだろう？

2-1で、レンダリング（3D → 写真）は情報を捨てることを見ました。捨てた情報を逆向きに計算する式はありません。その代わり、刑事が目撃者の話を聞きながらモンタージュを直していくように、3Dのカップを当て推量してレンダラーで描き、写真と比べて直します。これが逆レンダリングの最も基本的な考え方、「合成による分析」です。問題は何枚描くべきかです。

なぜこのテーマか

1逆に解く式はない

レンダリングは情報を捨てるので（2-1）、写真から3Dを直接計算する式はありません。その代わり「この3Dなら写真はこう写る」という前向きの計算は簡単です。だから描いて比べます（合成による分析）[1]。

2描くのにお金がかかる

モンタージュ一枚がレンダリング一回です。いくつかの数字を見つけるのに何枚必要かで、方法の使いどころが決まります。同じ枚数なら格子よりランダムの方が良いという結果は、機械学習の設定探しでも知られています[2]。

3微分可能レンダリングの出発点

当て推量・描く・比べる・直すの輪を速く回すことが、現代の逆レンダリングの核心です。その「直す」を一度にやる方法が次の編（2-3）です[3]。

全体像 — 当て推量、描く、比べる、直すの輪

1モンタージュ

手描きモンタージュ — 描いて比べる

モデル：ずれ = 1 − (写真 ∩ モンタージュ) ÷ (写真 ∪ モンタージュ)日常：目撃者の話を聞きながらモンタージュを描き直す

日常でたとえると

モンタージュ画家は目撃者の頭の中の顔を直接見ることはできません。その代わり描いて見せ、「目がもっと大きかった」という言葉を聞いて直します。何度かやり取りすれば、よく似た顔になります。

モデルでは

正解のカップの数字4つ（半径、高さ、左右、上下）は隠されています。数字を当て推量してレンダラーで描いたモンタージュを写真と重ねて見比べ、違いの度合い（損失、ここでは 1 − 重なり率）を測ります。赤（写真だけ）と青（モンタージュだけ）を見て数字を直します。これが合成による分析です[1]。

初心者のための解説 — レンダラーを逆に使う方法

  1. 逆ではなく、前へ何度も。 写真から数字を直接計算できないので、数字から写真を描いて比べます。
  2. 比べることで方向が分かる。 赤が右側に多ければモンタージュを右へ、上下で赤が多ければ高さを大きくします。人は絵を見れば方向が分かります。
  3. 数字4つなら何回かで済む。 手でやってみると、20回前後でずれを5%より下に減らせます。

この欄の限界 → 人が絵を見て直す代わりに、コンピュータに一人で探させるには？一番簡単な方法は、たくさん描いてみることです。どうやってたくさん描くか？ 次の欄へ。

数式で見る — 逆レンダリングを最適化として

数字 θ = (半径, 高さ, 左右, 上下)、レンダラー R、写真 I。逆レンダリングを θ* = argmin_θ L(R(θ), I) に置き換えます。ここで L はシルエットのずれ 1 − |A ∩ B| / |A ∪ B|（重なり率、IoUの補数）です。レンダラーを逆に解かず、前向きだけに使うことが「合成による分析」の核心です[1]。

助手

赤が見えるほうへ広げ、青が見えるほうは縮める。やってみると思ったより早く合います！

2探す

格子とランダム — 同じ81枚、違う結果

モデル：格子 = 数字ごとにn個の区間のすべての組み合わせ · ランダム = 適当に81枚日常：運動場で失くした鍵を探す — 碁盤の目に歩くか、散らばって探すか

日常でたとえると

運動場で鍵を探します。碁盤の目のように列を揃えて歩けば漏れはなさそうですが、決まった歩数の中では列の間隔が広くなります。あちこちに散らばって探せば、同じ歩数でもより多くの場所をのぞけます。

モデルでは

格子探しは、数字ごとに範囲を区間に分け、すべての組み合わせを描きます。数字4つを81枚でやると、数字ごとに3区間しかありません。ランダム探しは、81枚すべてで数字ごとに違う値を試します。結果に大きく効く数字がいくつかだけのとき、ランダムはその数字をより細かく調べます[2]。数字が増えると、格子の枚数は掛け算で増えます（次元の呪い）。

やってみよう — モンタージュ81枚ずつ

探す数字

動きで見る — 81枚が試した（半径、高さ）

初心者のための解説 — 枚数はどこに使われるか

  1. 数字4つ、81枚: 格子 17.7%、ランダム 11.2%。格子は半径を 0.73、1.0、1.27 の三つの値でしか試しませんでした。
  2. 格子を256枚に増やしても 12.7%。 数字ごとに4区間なら 4⁴ = 256枚です。ランダム81枚（11.2%）にも及びません。数字が一つ増えるたびに枚数は掛け算で増えます。
  3. 数字2つなら両方うまくいく。 81枚を数字2つに使えば、格子も数字ごとに9区間になるので 4.4%（ランダム 1.1%）です。

この欄の限界 → ランダムも11%で止まります。81枚は大まかな探しに使ったので、見つけた近くを細かく磨きましょう。次の欄へ。

数式で見る — 枚数と数字の数

数字 d 個、数字ごとに n 区間の格子は nᵈ 枚になります。同じ B 枚で格子を作ると、数字ごとに B^{1/d} 区間です（B = 81、d = 4 なら 3区間）。ランダム B 枚は数字ごとに B 個の異なる値を見ます。結果を決める数字が d 個より少ない k 個なら、ランダムはその k 個を B 区間近くまで細かく、格子は B^{1/d} 区間しか見ません[2]。

アバボット

同じ81枚なのに、格子は同じ半径を27回ずつ描いている。ランダムは一度も重ならないよ。これがお金の使い方ってものさ。

3磨く

磨きと曖昧さ — 細かく、でもゆっくり

モデル：数字ごとに±の歩幅で試す → 良くなれば採用、ダメなら歩幅を半分に日常：ラジオの周波数を少しずつ回して合わせる

日常でたとえると

昔のラジオは、ダイヤルを少しずつ回して一番きれいな音の場所を探します。行き過ぎたら戻し、だんだん小さく回します。ダイヤルが一つなら早いですが、数十個あれば一日中かかります。

モデルでは

ランダム81枚の最良から出発し、数字ごとに少し増やしてみて、減らしてみて、良くなれば採用します（磨き）。一周の間ずっと良くならなければ、歩幅を半分にします。数字4つなら一周で8枚です。そして、ずれを0に近づけても答えが一つかどうかは別に考える必要があります（曖昧さ、2-1）。

やってみよう — 一つずつ磨く

動きで見る — 大きさと距離の谷

初心者のための解説 — 磨きの値

  1. 0.6%まで。 ランダムの最良（11.2%）からモンタージュを96枚さらに描いて磨くと、ずれは0.6%になります。見つけた半径は 1.12、高さは 1.72（正解は 1.12、1.74）。
  2. 数字が多いと遅い。 一周ごとに数字の数 × 2枚を描きます。本物の3D形状を数千個の数字で表すと、一周で数千枚です。
  3. 谷。 カメラ距離が分からないとすると、カップの大きさと距離を一緒に変えた答えが斜めの帯になり、どれも写真とよく合います。磨きがその帯のどこで止まるかは、出発点次第です。

この欄の限界 → 直す方向を、数字ごとに二枚ずつ描いて見つける代わりに、一度に分かる方法はないでしょうか？ 微分を使えばよいのですが、シルエットの境界は階段のようにぷつんと切れていて、微分は0になります。次の編 2-3「階段とすべり台」へ。

数式で見る — 座標に沿って探す

数字 θᵢ ごとに θ ± δᵢ·eᵢ を描き、L が減れば移します。一周は 2d 回のレンダリング。一周の間良くならなければ δ ← δ/2。微分があれば、d 個の数字の直す方向（勾配）を、レンダリング一、二回分の値でまとめて得られます。これが微分可能レンダリングが逆レンダリングを速くする理由です[3]。

コード1 · 格子 vs ランダム — 同じ81枚で数字4つを探す、シード10回
# 코드 1 · 몽타주 그리기 — 컵 사진 한 장에서 숫자 넷(반지름, 높이, 좌우, 위아래)을 찾기: 격자 vs 무작위, 같은 81장
import numpy as np, itertools, time
def cyl(p, r, h):
    dx = np.hypot(p[..., 0], p[..., 2]) - r; dy = np.abs(p[..., 1]) - h/2
    return np.minimum(np.maximum(dx, dy), 0) + np.hypot(np.maximum(dx, 0), np.maximum(dy, 0))
def cup_handle(p, handle=True, hd=-90):
    """위가 열린 컵(반지름 1, 높이 1.6, 벽 0.14) + 손잡이 고리. hd = 손잡이 방향(도)"""
    body = np.maximum(cyl(p, 1, 1.6), -cyl(p - [0, .14, 0], .86, 1.6))
    if not handle: return body
    a = np.radians(hd); hx = np.cos(a)*p[..., 0] + np.sin(a)*p[..., 2]; hz = -np.sin(a)*p[..., 0] + np.cos(a)*p[..., 2]
    q = np.hypot(hx - 1.05, p[..., 1]) - .42; return np.minimum(body, np.hypot(q, hz) - .09)
def silhouette(sdf, az, el=15, dist=4.5, f=2.2, res=48):
    """카메라가 물체 둘레 az도, 위로 el도에서 원점을 본다. 광선을 따라 걷기(sphere tracing)로 맞은 픽셀만 1"""
    a, e = np.radians(az), np.radians(el); pos = dist*np.array([np.sin(a)*np.cos(e), np.sin(e), np.cos(a)*np.cos(e)])
    fw = -pos/np.linalg.norm(pos); rt = np.array([fw[2], 0, -fw[0]]); rt /= np.linalg.norm(rt); up = np.cross(rt, fw)
    u, v = np.meshgrid((np.arange(res) + .5)/res*2 - 1, 1 - (np.arange(res) + .5)/res*2)
    d = fw*f + rt*u[..., None] + up*v[..., None]; d /= np.linalg.norm(d, axis=-1, keepdims=True)
    t = np.zeros(u.shape); hit = np.zeros(u.shape, bool)
    for _ in range(80):
        s = sdf(pos + d*t[..., None]); hit |= s < 1e-3; t = np.where(hit, t, t + .9*s)
    return hit & (t < 40)
def cup(r, h, x, y):
    """위가 열린 컵(벽 0.14), 자리 (x, y)로 옮김"""
    return lambda p: np.maximum(cyl(p - [x, y, 0], r, h), -cyl(p - [x, y + .14, 0], r - .14, h))
TRUE = (1.12, 1.74, .27, -.18); RANGE = [(.6, 1.4), (1.0, 2.4), (-.5, .5), (-.5, .5)]
photo = silhouette(cup(*TRUE), 0, res=24)                         # 정답 사진 (숫자는 비밀)
def loss(theta):                                                 # 어긋남 = 1 − 겹친 비율
    m = silhouette(cup(*theta), 0, res=24); return 1 - (m & photo).sum()/(m | photo).sum()
t0 = time.time()
levels = [[lo + (hi - lo)*(i + .5)/3 for i in range(3)] for lo, hi in RANGE]
grid_best = min(loss(t) for t in itertools.product(*levels))                       # 3 × 3 × 3 × 3 = 81장
rand_best = []
for seed in range(1, 11):
    g = np.random.default_rng(seed); rand_best.append(min(loss([g.uniform(lo, hi) for lo, hi in RANGE]) for _ in range(81)))
print(f"격자 81장 최선 어긋남: {100*grid_best:.1f}%")
print("무작위 81장 최선 (시드 10번): " + " ".join(f"{100*v:.1f}" for v in rand_best) + f"  → 평균 {100*np.mean(rand_best):.1f}%")
print(f"무작위가 격자보다 나은 횟수: {sum(v < grid_best for v in rand_best)} / 10 · 계산 {time.time() - t0:.0f}초")

    q = np.hypot(hx - 1.05, p[..., 1]) - .42; return np.minimum(body, np.hypot(q, hz) - .09)
def silhouette(sdf, az, el=15, dist=4.5, f=2.2, res=48):
    """카메라가 물체 둘레 az도, 위로 el도에서 원점을 본다. 광선을 따라 걷기(sphere tracing)로 맞은 픽셀만 1"""
    a, e = np.radians(az), np.radians(el); pos = dist*np.array([np.sin(a)*np.cos(e), np.sin(e), np.cos(a)*np.cos(e)])
    fw = -pos/np.linalg.norm(pos); rt = np.array([fw[2], 0, -fw[0]]); rt /= np.linalg.norm(rt); up = np.cross(rt, fw)
    u, v = np.meshgrid((np.arange(res) + .5)/res*2 - 1, 1 - (np.arange(res) + .5)/res*2)
    d = fw*f + rt*u[..., None] + up*v[..., None]; d /= np.linalg.norm(d, axis=-1, keepdims=True)
    t = np.zeros(u.shape); hit = np.zeros(u.shape, bool)
    for _ in range(80):
        s = sdf(pos + d*t[..., None]); hit |= s < 1e-3; t = np.where(hit, t, t + .9*s)
    return hit & (t < 40)
def cup(r, h, x, y):
    """위가 열린 컵(벽 0.14), 자리 (x, y)로 옮김"""
    return lambda p: np.maximum(cyl(p - [x, y, 0], r, h), -cyl(p - [x, y + .14, 0], r - .14, h))
TRUE = (1.12, 1.74, .27, -.18); RANGE = [(.6, 1.4), (1.0, 2.4), (-.5, .5), (-.5, .5)]
photo = silhouette(cup(*TRUE), 0, res=24)                         # 정답 사진 (숫자는 비밀)
def loss(theta):                                                 # 어긋남 = 1 − 겹친 비율
    m = silhouette(cup(*theta), 0, res=24); return 1 - (m & photo).sum()/(m | photo).sum()
t0 = time.time(); g = np.random.default_rng(1)
cands = [[g.uniform(lo, hi) for lo, hi in RANGE] for _ in range(81)]; theta = min(cands, key=loss); L = loss(theta); n = 81
step = [.1, .17, .12, .12]
print(f"출발 (무작위 81장 최선): 어긋남 {100*L:.1f}%  숫자 {np.round(theta, 2)}")
for rnd in range(1, 13):
    better = False
    for i in range(4):
        for sgn in (1, -1):
            t = list(theta); t[i] += sgn*step[i]; l = loss(t); n += 1
            if l < L: theta, L, better = t, l, True
    if not better: step = [s/2 for s in step]                     # 한 바퀴 내내 안 나아지면 보폭 절반
    if rnd % 3 == 0: print(f"  {rnd:2d}바퀴 · 지금까지 {n:3d}장 · 어긋남 {100*L:5.1f}%  숫자 {np.round(theta, 2)}")
print(f"정답 숫자 {TRUE} · 한 바퀴 = 숫자 4개 × 2 = 8장 · 계산 {time.time() - t0:.0f}초")
