Staircase and slide — blurring the edge reveals which way to fix

Core question · Without drawing two sketches per parameter, can one sketch tell you which way to fix all four parameters at once?

In 2-2's refinement, each tweak of one parameter cost two sketches (montage). With the derivative (gradient) you know the direction at once. But a silhouette's pixels are either 0 or 1, so the mismatch is a staircase, not a smooth slope. A ball on a staircase does not roll. Blurring the edge slightly to turn the staircase into a slide is the core idea of differentiable rendering.

Why this topic

1Drawing is not differentiable

Whether a pixel is covered is either 0 or 1. Even if you change a parameter slightly, most pixels stay the same, so the gradient is almost always zero. This was the first wall that studies fitting 3D meshes to photos ran into[2].

2Differentiate approximately anyway

In 2014, a study came out that approximately differentiated the renderer and fit the shape and pose of a person using gradients[1]. Since then, the method of blurring the edge like a probability to get gradients everywhere has become widely used[3].

3The more parameters, the bigger the gap

Refinement costs two sketches per parameter. Differentiation needs just one sketch and one backward calculation, no matter how many parameters there are. It is the basis for fitting a 3D shape with thousands of parameters to a photo[4].

Big picture — turning the staircase into a slide

1Staircase

Staircase — a hard edge has no gradient

Model: pixel = covered (1) or not covered (0) → the mismatch is a step functionEveryday: a ball left on a staircase

In everyday terms

Put a ball on a slide and it rolls down the way the slide slopes. The slope tells it the direction. Put it on a stair tread and it's flat, so it rolls nowhere. At the edge it just drops off.

In the model

Gradient is how much the mismatch changes when you change a parameter very slightly (derivative). But the silhouette's pixels are 0 or 1. If you increase the radius by 0.001 and the edge doesn't cross into the next pixel, no pixel changes and the mismatch stays the same. So the mismatch is a staircase, with gradient 0 on the treads and endlessly large at the edges[2].

Beginner's explanation — why is it 0?

  1. A slope from afar. Looking at radius 0.6~1.4 in steps of 0.01, the mismatch falls toward the correct value (1.12), a valley.
  2. A staircase up close. Looking at 1.10~1.14 in 81 steps of 0.0005, 94% of the cells have the same mismatch as the neighboring cell. There are only 6 distinct values, six steps of the staircase.
  3. The gradient gives no direction. It's 0 on the treads, and jumps by one pixel at the edges. The refinement in 2-2 jumped by 0.1 at a time, so it didn't know about the staircase, but it drew two sketches per parameter instead.

Limit of this panel → If the exact gradient is zero, differentiation is useless. Can we turn the staircase into a slide? Yes, just blur the edge slightly. Next panel.

The math — derivative of the step function

Pixel value Sᵢ(θ) = [mᵢ(θ) < 0], where mᵢ is the closest distance the ray i gets to the cup (negative if it passes through). The brackets are 1 if true, 0 if false. ∂Sᵢ/∂θ = 0 (except at the instant mᵢ = 0). So the gradient of L = 1 − IoU is also almost always zero. If you measure with the difference (L(θ+δ) − L(θ−δ))/2δ, you get 0 by bad luck, and if you happen to catch the edge, it swings wildly depending on δ (code 1, ③).

2Slide

Slide — blurring the edge

Model: degree of coverage S = 1 ÷ (1 + em/τ), τ = blur widthEveryday: blurry glasses make the edges look soft

In everyday terms

When you wear blurry glasses, the edge of a cup doesn't break off sharply but fades gradually. Even if the cup gets a little bigger, the faint band at the edge gets a bit darker. Even tiny changes show up.

In the model

Measure the closest distance m the ray gets to the cup, and draw the degree of pixel coverage as a value between 0 and 1 (soft silhouette). Rays that pass through the cup are near 1 (the thinner the wall, the less dark when τ is large), far outside is 0, and near the edge it's in between. The larger the blur width τ, the wider the blur. Now even a small change in the parameters changes the edge pixel values slightly, so the mismatch becomes a smooth slide, with a gradient everywhere[3]. The gradient is obtained by backward calculation rather than by drawing again.

Try it yourself — change the blur width τ

τ (blur width)

See it in action — a line crossing the edge

Beginner's explanation — pros and cons of blurring

  1. A gradient appears. When τ = 0, all four parameters have zero gradient. When τ = 0.05, from the first guess (radius 0.8), the direction "increase the radius, increase the height" comes out of one sketch (montage).
  2. The more it blurs, the farther you can sense. The blurred edge spreads wide, so you know the direction even if the sketch and the photo barely overlap.
  3. Too much blur pushes you off target. When matching blurry pictures, the lowest point shifts away from the correct answer. The correct radius is 1.12, but with τ = 0.12 the lowest point is at 1.09, and with τ = 0.25 at 0.99.

Limit of this panel → A large blur pulls from far away but is imprecise; a small blur is precise but works only up close. To use both, what do we do? Start with a large τ and decrease it gradually. Next panel.

The math — soft silhouette and backward calculation

Sᵢ = σ(−mᵢ/τ) = 1/(1 + emᵢ/τ), L = (1/N) Σ (Sᵢ − Tᵢ)² (T is the photo). By the chain rule, ∂L/∂θ = (1/N) Σ 2(Sᵢ − Tᵢ) · (−Sᵢ(1 − Sᵢ)/τ) · ∂mᵢ/∂θ. Since mᵢ is the value of the distance function at the closest point p* on the ray, ∂mᵢ/∂θ = ∂f(p*; θ)/∂θ. You only need to re-measure the distance function at p*, so there's no need to draw again. Soft Rasterizer uses the same idea for the triangles of a mesh (turning the distance to the boundary into a probability)[3].

3Riding the slide

Riding the slide — reduce τ while descending along the gradient

Model: gradient descent (Adam step size) + blur width 0.12 → 0.01Everyday: coming down a foggy mountain by looking only at the slope under your feet

In everyday terms

On a foggy mountain you can't see far, but you can feel the slope under your feet. Take one step at a time downhill and you reach the valley. First big strides, then careful steps as the bottom gets near.

In the model

Each step draws one soft sketch (montage) to get 4 gradients, and nudges all 4 parameters a little downhill together (gradient descent). Each step size is matched to the size of the gradient for each parameter (Adam[5]). τ starts at 0.12 and is reduced each step down to 0.01. At first it pulls from afar; at the end it hits the target exactly. The comparison is the refinement from 2-2, run from the same starting point.

  2. Even a far start works. From a guess that barely overlaps the photo (mismatch 83.3%), the blurred edges still let you find the direction, reaching 2.8% at 40 steps (refinement with 40 sketches: 18.8%).
  3. One step costs more. The soft sketch carefully finds the closest point for each ray and also does a backward calculation. So it takes about the time of 1.5 hard sketches (measured in Chrome; larger with a bigger blur width, about 1.8 with numpy in Colab). Still cheaper than one round of refinement (8 sketches).

The math — gradient descent and the blur schedule

At step t, τₜ = max(0.01, 0.12 · 0.92ᵗ), gradient gₜ = ∂L_τₜ/∂θ. Adam[5]: mₜ = 0.9mₜ₋₁ + 0.1gₜ, vₜ = 0.999vₜ₋₁ + 0.001gₜ², θ ← θ − ηₜ · m̂ₜ/(√v̂ₜ + ε), ηₜ = 0.08 · 0.95ᵗ. Refinement renders 2d times per round; slide descent renders once per step plus one backward calculation, regardless of the number of parameters d. A real differentiable renderer does the backward calculation by automatic differentiation[4].

Code 1 · Staircase and slide — the zoomed staircase, the lowest point by τ, and the gradient at the first guess
# 코드 1 · 계단과 미끄럼틀 — 반지름만 바꾸며 딱딱한 어긋남과 부드러운 어긋남을 재고, 기울기를 본다
import numpy as np
def cyl(p, r, h):
    dx = np.hypot(p[..., 0], p[..., 2]) - r; dy = np.abs(p[..., 1]) - h/2
    return np.minimum(np.maximum(dx, dy), 0) + np.hypot(np.maximum(dx, 0), np.maximum(dy, 0))
def cup(r, h, x, y):
    """위가 열린 컵(벽 0.14), 자리 (x, y)로 옮김"""
    return lambda p: np.maximum(cyl(p - [x, y, 0], r, h), -cyl(p - [x, y + .14, 0], r - .14, h))
def rays(az=0, el=15, dist=4.5, f=2.2, res=24):
    a, e = np.radians(az), np.radians(el); pos = dist*np.array([np.sin(a)*np.cos(e), np.sin(e), np.cos(a)*np.cos(e)])
    fw = -pos/np.linalg.norm(pos); rt = np.array([fw[2], 0, -fw[0]]); rt /= np.linalg.norm(rt); up = np.cross(rt, fw)
    u, v = np.meshgrid((np.arange(res) + .5)/res*2 - 1, 1 - (np.arange(res) + .5)/res*2)
    d = fw*f + rt*u[..., None] + up*v[..., None]; return pos, d/np.linalg.norm(d, axis=-1, keepdims=True)
POS, D = rays(); TS = np.linspace(4.5 - 2.6, 4.5 + 2.6, 400)          # 광선 위 400점 (촘촘히)
PTS = POS + D[..., None, :]*TS[:, None]                                  # 24×24×400×3
def closest(theta):
    """광선마다 컵에 가장 가까이 간 거리 m (뚫으면 음수)"""
    return cup(*theta)(PTS).min(axis=-1)
def coverage(theta, tau):
    m = closest(theta)
    return (m < 0).astype(float) if tau == 0 else 1/(1 + np.exp(np.clip(m/tau, -40, 40)))
TRUE = (1.12, 1.74, .27, -.18); photo = coverage(TRUE, 0) > .5
def hard_loss(th): s = coverage(th, 0) > .5; return 1 - (s & photo).sum()/(s | photo).sum()
def soft_loss(th, tau): return ((coverage(th, tau) - photo)**2).mean()
print("① 계단: 반지름만 1.10→1.14를 0.0005씩 (나머지는 정답)")
rs = np.arange(1.10, 1.14 + 1e-9, .0005); hl = np.array([hard_loss((r, *TRUE[1:])) for r in rs])
print(f"   81칸 중 옆 칸과 어긋남이 같은 곳 {np.mean(hl[1:] == hl[:-1])*100:.0f}% · 서로 다른 값(계단 수) {len(np.unique(hl.round(6)))}개")
print("② 미끄럼틀: 반지름 0.6→1.4 (0.02씩)에서 어긋남이 가장 낮은 반지름")
rs = np.arange(.6, 1.4 + 1e-9, .02)
for tau in (0, .02, .05, .12, .25):
    L = [hard_loss((r, *TRUE[1:])) if tau == 0 else soft_loss((r, *TRUE[1:]), tau) for r in rs]
    print(f"   τ = {tau:<4}: 가장 낮은 반지름 {rs[int(np.argmin(L))]:.2f} (정답 1.12)")
print("③ 첫 짐작(0.8, 1.3, 0, 0)에서 숫자마다의 기울기 (숫자를 ±0.01 바꿔 잰 값)")
g0 = np.array([.8, 1.3, 0, 0])
for tau in (0, .05):
    f = (lambda t: hard_loss(t)) if tau == 0 else (lambda t: soft_loss(t, tau))
    g = [(f(g0 + .01*np.eye(4)[i]) - f(g0 - .01*np.eye(4)[i]))/.02 for i in range(4)]
    print(f"   τ = {tau:<4}: 반지름 {g[0]:+.3f}  높이 {g[1]:+.3f}  좌우 {g[2]:+.3f}  위아래 {g[3]:+.3f}")

Code 2 · Riding the slide — fixing 4 parameters with the soft silhouette's gradient vs refinement
# 코드 2 · 미끄럼 타기 — 부드러운 실루엣의 기울기로 숫자 4개를 한꺼번에 고치기 vs 2-2의 다듬기
import numpy as np, time
def cyl(p, r, h):
    dx = np.hypot(p[..., 0], p[..., 2]) - r; dy = np.abs(p[..., 1]) - h/2
    return np.minimum(np.maximum(dx, dy), 0) + np.hypot(np.maximum(dx, 0), np.maximum(dy, 0))
def cup(r, h, x, y):
    return lambda p: np.maximum(cyl(p - [x, y, 0], r, h), -cyl(p - [x, y + .14, 0], r - .14, h))
def rays(az=0, el=15, dist=4.5, f=2.2, res=24):
    a, e = np.radians(az), np.radians(el); pos = dist*np.array([np.sin(a)*np.cos(e), np.sin(e), np.cos(a)*np.cos(e)])
    fw = -pos/np.linalg.norm(pos); rt = np.array([fw[2], 0, -fw[0]]); rt /= np.linalg.norm(rt); up = np.cross(rt, fw)
    u, v = np.meshgrid((np.arange(res) + .5)/res*2 - 1, 1 - (np.arange(res) + .5)/res*2)
    d = fw*f + rt*u[..., None] + up*v[..., None]; return pos, d/np.linalg.norm(d, axis=-1, keepdims=True)
POS, D = rays(); TS = np.linspace(4.5 - 2.6, 4.5 + 2.6, 400); PTS = POS + D[..., None, :]*TS[:, None]
TRUE = np.array([1.12, 1.74, .27, -.18])
photo = cup(*TRUE)(PTS).min(-1) < 0
def hard_loss(th):
    s = cup(*th)(PTS).min(-1) < 0; return 1 - (s & photo).sum()/(s | photo).sum()
def soft_grad(th, tau):
    """부드러운 몽타주 1장 + 거꾸로 계산: 어긋남 L = 평균 (S − 사진)², 기울기 ∂L/∂숫자.
       광선마다 컵에 가장 가까운 점 p*를 찾고, 그 점에서만 숫자를 조금 바꾼 거리 값을 다시 잰다(다시 그리지 않음)"""
    v = cup(*th)(PTS); k = v.argmin(-1); m = np.take_along_axis(v, k[..., None], -1)[..., 0]
    pstar = np.take_along_axis(PTS, k[..., None, None].repeat(3, -1), -2)[..., 0, :]
    S = 1/(1 + np.exp(np.clip(m/tau, -40, 40))); r = S - photo
    c = 2*r*(-S*(1 - S)/tau)                                         # ∂L/∂m (픽셀마다)
    g = np.array([(c*(cup(*(th + 1e-3*e))(pstar) - cup(*(th - 1e-3*e))(pstar))/2e-3).mean() for e in np.eye(4)])
    return (r**2).mean(), g
def slide(start, steps):
    th = np.array(start, float); m = np.zeros(4); s = np.zeros(4); log = []
    for it in range(steps):
        tau = max(.01, .12*.92**it); lr = .08*.95**it                  # 번짐 폭과 보폭을 점점 줄인다
        _, g = soft_grad(th, tau)
        m = .9*m + .1*g; s = .999*s + .001*g*g                           # Adam: 숫자마다 보폭을 맞춘다
        th -= lr*(m/(1 - .9**(it + 1)))/(np.sqrt(s/(1 - .999**(it + 1))) + 1e-8)
        log.append(hard_loss(th))
    return th, log
def hill(start, budget):
    th = np.array(start, float); L = hard_loss(th); n = 1; st = np.array([.1, .17, .12, .12]); log = [L]
    while n < budget:
        better = False
        for i in range(4):
            for sg in (1, -1):
                if n >= budget: break
                t = th.copy(); t[i] += sg*st[i]; l = hard_loss(t); n += 1
                if l < L: th, L, better = t, l, True
                log.append(L)
        if not better: st /= 2
    return th, log
start = (.8, 1.3, 0, 0); print(f"첫 짐작 {start} · 어긋남 {100*hard_loss(start):.1f}%")
t0 = time.time(); th_s, ls = slide(start, 60); t1 = time.time(); th_h, lh = hill(start, 60); t2 = time.time()
print(" 횟수 | 미끄럼 (걸음) | 다듬기 (장)")
for n in (10, 20, 27, 40, 60): print(f"  {n:3d} |   {100*ls[n-1]:5.1f}%    |  {100*lh[n-1]:5.1f}%")

        Example values and illustrative models

        • The correct cup and camera are the same as in 2-2. The "near guess" first guess is radius 0.8, height 1.3, left/right 0, up/down 0 (mismatch 48.0%), and the "far guess" is radius 0.6, height 1.0, left/right −0.5, up/down 0.5 (mismatch 83.3%).
        • The soft silhouette finds the closest distance to the cup for each ray with long strides and golden-ratio narrowing, and draws the degree of coverage as 1/(1 + em/τ). The gradient was obtained from the distance function value after changing a parameter by ±0.005 at the closest point (no redrawing). The soft mismatch is the mean of (S − photo)², and the reported result is always the hard 1 − overlap ratio (IoU).
        • The slide's step size (Adam, starting at 0.08 and multiplied by 0.95 each step) and the blur schedule (starting at 0.12 and multiplied by 0.92 each step, never going below 0.01) are example values chosen for this cup. Refinement uses the same step size and rules as 2-2.
